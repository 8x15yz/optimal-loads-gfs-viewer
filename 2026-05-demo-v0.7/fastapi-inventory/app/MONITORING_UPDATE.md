# 모니터링 변경 사항 — Blue-X 중계 요청 식별 (2026-10-15)

## 적용

반영 파일: request_logging.py, monitoring.py, templates/monitoring.html (테스트: tests/test_monitoring.py).
기존과 같이 앱 재시작 또는 이미지 재빌드로 교체함. DB 마이그레이션 없음. 시작 시 request_id, relay_account 인덱스가 추가로 생성됨.

## 동작

- 요청에 `X-Request-ID`가 있으면 그 값을 요청 ID로 기록하고 응답 헤더에도 그대로 돌려줌. Blue-X는 활동 로그 ID를 이 헤더로 보내므로, Blue-X 콘솔과 모니터링 화면의 요청 ID가 같은 값이 됨. 헤더가 없거나 형식이 맞지 않으면(영문·숫자·`.` `_` `:` `-`, 8~128자) 기존처럼 서버가 생성함.
- 요청에 `X-BlueX-Account`가 있으면 `relay_account`로 기록함(영문·숫자·`.` `_` `:` `@` `-`, 최대 128자).
- DB 문서의 `_id`는 항상 서버가 생성함. 같은 요청 ID가 다시 들어와도 저장 충돌이 없음. 기존 기록은 `_id`와 `request_id`가 같은 값으로 그대로 유지됨.
- 새 필드: `request_id_source`(`header` = 중계 서버 전달값, `server` = 서버 생성), `relay_account`.
- 화면: 조회 조건에 ‘요청 ID’, ‘Blue-X 계정’ 추가(정확히 일치). 클라이언트 IP 패널 아래 ‘Blue-X 계정’ 상위 10개 표 추가. 요청 이력의 IP 아래에 Blue-X 계정을 표시하고, 요청 상세에 계정과 요청 ID 출처를 표시함.
- 두 헤더는 누구나 보낼 수 있는 값이므로 인증 정보가 아님. 출처는 클라이언트 IP·User-Agent와 함께 판단함.
- 요청 ID 검색도 선택한 조회 기간(최대 7일) 안에서만 동작함.

## 검증

기존 테스트 16개와 신규 테스트 1개(헤더 기록, 형식 오류 무시, 같은 ID 재사용, 요청 ID·계정 필터, 계정 집계, 화면 요소) 통과. 모의 데이터로 화면 렌더링 확인. 실제 운영 DB 접속·배포는 하지 않음.

# 모니터링 변경 사항

## 적용

이 ZIP은 기존과 동일하게 app/ 내부 파일 구조입니다. 운영 코드에 반영할 주요 파일은 아래 3개입니다.

- monitoring.py
- request_logging.py
- templates/monitoring.html

기존 배포 방식으로 앱을 재시작하거나 이미지를 다시 빌드하여 교체합니다. 구버전 워커/컨테이너를 모두 종료한 뒤 새 버전으로 시작하세요. 구버전이 남아 있으면 자동 삭제 인덱스를 다시 만들 수 있습니다.

## 동작

- /monitoring 및 /api/monitoring/ 아래 요청은 계속 기록하되 기본 조회에서 제외합니다. 목록, 요약, 그래프, 엔드포인트/IP 통계, P95에 동일하게 적용됩니다.
- ‘모니터링 요청 포함’을 켜면 전체에 포함됩니다. 요청 종류에서 ‘모니터링’을 명시적으로 선택하면 모니터링 기록만 조회합니다.
- 요청 이력 표에 User-Agent 열을 추가했습니다. 긴 문자열은 줄바꿈되며 값이 없으면 —로 표시됩니다. 기존 상세 펼침에도 표시됩니다.
- 로그는 기간에 따른 자동 삭제 없이 영구 보관합니다. 기존 REQUEST_LOG_RETENTION_DAYS 환경변수는 더 이상 사용하지 않으므로 남아 있어도 30일 삭제가 다시 활성화되지 않습니다.
- 앱 시작 시 request_logs 컬렉션의 기존 request_expiry TTL 인덱스를 제거합니다. 컬렉션명은 MONGO_REQUEST_LOGS_COL 설정을 따릅니다. 기존 문서의 expires_at 필드는 남아 있어도 해당 TTL 인덱스가 없으면 이 규칙에 의해 삭제되지 않습니다. 새 기록에는 expires_at을 넣지 않습니다.
- DB 계정에는 인덱스 조회·삭제·생성 권한이 필요합니다. 해제 실패 시 화면에 경고가 표시되고 이후 재시도합니다. 경고가 남아 있으면 기존 기록은 여전히 만료 삭제될 수 있으므로 권한과 서버 로그를 확인하세요.
- 이미 삭제된 기록을 복원하는 변경은 아닙니다. 조회 기간 선택은 기존 최근 1시간/6시간/24시간/7일을 유지합니다. 저장 기간과 화면 조회 범위는 별개입니다.

## 검증

모의 MongoDB를 이용한 기존 기능 및 회귀 테스트: 기본 제외/명시적 포함, 통계 일치, User-Agent 전달, 기존 TTL 제거와 문서 보존, 재시작, 해제 실패 후 재시도. 실제 운영 DB에 접속하거나 배포하지 않았습니다.

테스트 실행: `python -m pytest --import-mode=importlib tests/test_monitoring.py test_monitoring.py -q`

테스트 의존성: pytest, mongomock, fastapi, motor, httpx, jinja2, uvicorn.
