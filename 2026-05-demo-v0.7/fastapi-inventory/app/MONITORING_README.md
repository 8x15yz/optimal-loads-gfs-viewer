# GET 요청 모니터링 추가본

기존 FastAPI 서비스에 `/monitoring` 운영자 대시보드를 추가했습니다.
원래 기상·타일·ZIP API의 처리 로직은 변경하지 않았습니다.

## 적용

이 ZIP의 루트는 기존 `app/` 디렉터리의 내용입니다. 현재 배포 파일을 백업한 뒤,
같은 위치에 아래 변경·추가 파일을 반영하세요.

변경: `main.py`, `db.py`, `templates/components/topbar.html`
추가: `request_logging.py`, `monitoring.py`, `templates/monitoring.html`
검증·안내: `tests/test_monitoring.py`, `MONITORING_README.md`

1. 기존 서비스 환경변수에 `MONITORING_USERNAME`과 `MONITORING_PASSWORD`를 설정합니다.
   - 사용자명 예: `operator`
   - 비밀번호: 운영자가 정한 충분히 긴 별도 비밀번호. 코드에는 기본 비밀번호가 없습니다.
   - `.env`가 실제 실행 프로세스에 로드되는지 확인하세요. Docker의 `env_file`/`environment`를 사용한다면 해당 설정에 넣습니다.
2. 변경 파일이 포함되도록 기존 배포 방식으로 API 서비스를 재시작합니다.
   컨테이너 이미지에 코드를 복사하는 방식이면 이미지를 다시 빌드하여 재생성합니다.
3. HTTPS로 기존 서비스의 `/monitoring`에 접속하고 브라우저 로그인 창에 운영자 계정을 입력합니다.
4. `/api/griddata` 등 실제 API를 호출한 뒤 수 초 후 대시보드를 조회합니다.
   없는 경로를 호출해 404 기록도 확인할 수 있습니다.

기존 MongoDB 연결을 재사용하며 추가 프런트엔드 라이브러리·별도 서버·크론 작업은 없습니다.
환경변수 미설정 시 모니터링 화면과 조회 API는 503으로 닫힙니다. GET 기록 자체는 계속 동작합니다.
운영자 인증은 HTTP Basic이므로 외부 접근은 반드시 기존 HTTPS 경로를 사용하세요.
API 이용자는 운영자 계정을 사용할 필요가 없습니다.
이 비밀번호는 모니터링 화면과 조회 API만 보호하며 기존 관리 페이지의 접근 정책은 바꾸지 않습니다.

## 설정

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `MONITORING_USERNAME` | 없음, 필수 | 운영자 사용자명 |
| `MONITORING_PASSWORD` | 없음, 필수 | 운영자 비밀번호 |
| `MONGO_REQUEST_LOGS_COL` | `request_logs` | 요청 로그 전용 컬렉션 |
| `REQUEST_LOG_RETENTION_DAYS` | `30` | 새 기록의 보관 일수, 정수 1~365 |

보관 기간은 각 기록의 `expires_at`에 저장합니다. 환경변수 변경은 이후 생성되는 기록부터 적용됩니다.
MongoDB TTL 인덱스로 만료 기록을 자동 정리하며 만료 시각과 실제 삭제 시각에는 지연이 있을 수 있습니다.
앱 DB 계정에는 새 컬렉션 생성·읽기·쓰기와 인덱스 생성 권한이 필요합니다.
인덱스 생성이 실패하면 서버 로그와 대시보드에 상태를 알리고 이후 요청 처리 중 재시도합니다.
기록은 앱 시작 이후부터 쌓이며 기존 서버 접근 기록을 자동으로 가져오지는 않습니다.

## 화면

- 최근 1시간 / 6시간 / 24시간 / 7일 조회
- 전체 GET / 데이터 API / 수집 관리 API / 화면 / 정적 파일 / 모니터링 / 미등록 경로 구분
- HTTP 상태 그룹, 경로 부분 일치, IP 정확 일치 필터
- 요청 수, 4xx·5xx 오류율, 평균·P95 서버 처리 시간
- 시간대별 요청 그래프, 엔드포인트 상위 15개, IP 상위 10개
- 최신 요청 50건씩 조회, 최대 1,000페이지
- 파라미터, User-Agent, 요청 ID, 예외 종류, 응답 전송 완료 여부 펼쳐 보기
- 30초 자동 갱신: 첫 페이지이며 브라우저 탭이 보일 때만 동작
- 저장은 UTC, 화면은 KST 표시

전체 GET에는 대시보드 자신의 요청도 들어갑니다. 실제 데이터 이용만 보려면 `데이터 API`를 선택하세요.
정적 파일은 `/guide/{path}`, `/svgs/{path}`로 묶고 미등록 경로는 `[unmatched]`로 묶습니다.
라우팅 전에 발생하는 리다이렉트·오류 등은 등록 경로 정보가 없을 수 있습니다.
API가 응답을 만들지 못하고 취소되면 내부 기록상 499로 표시할 수 있습니다. 실제 전송된 HTTP 응답을 의미하지는 않습니다.
등록 API에서 발생한 처리되지 않은 예외는 500으로 기록하고 원래 예외 처리는 유지합니다.

## IP를 해석하는 방법

로그는 ASGI의 `scope['client']`를 사용합니다. 사용자가 임의로 보낸
`X-Forwarded-For` 또는 `X-Real-IP`를 이 코드가 직접 신뢰하지 않습니다.

프록시 없이 앱에 직접 연결하면 보통 직접 연결한 클라이언트 IP가 보입니다.
Nginx·로드밸런서 뒤에서 실행하면 아래 두 조건이 맞아야 원래 클라이언트 IP가 보입니다.

1. 프록시가 실제 연결에 근거한 전달 헤더를 설정합니다.
2. Uvicorn의 proxy headers 처리가 활성화되고, `--forwarded-allow-ips` 또는
   `FORWARDED_ALLOW_IPS`가 실제로 신뢰하는 프록시의 주소만 포함합니다.

인터넷 요청을 직접 받는 환경에서 무조건 `*`로 신뢰 범위를 열지 마세요.
프록시와 앱 사이의 실제 네트워크 설정은 이번 ZIP에 없어 검증하지 않았습니다.
현재 프록시 주소만 보인다면 배포 설정 확인이 필요합니다.
여러 사용자가 NAT·VPN·기관망의 같은 공인 IP를 공유할 수 있으므로 IP는 사람·기관의 확정 식별자가 아닙니다.

## 기록 범위와 성능

- FastAPI까지 도착한 GET 요청을 기록합니다. POST·HEAD·OPTIONS 등은 기록하지 않습니다.
- 앞단 프록시가 직접 응답하거나 차단한 요청, 프록시가 직접 제공하는 정적 파일은 앱에 도착하지 않아 기록되지 않습니다.
- MongoDB에는 URL 발급 API의 요청·응답 결과가 기록됩니다. S3에서 실제 파일을 다운로드했는지나 다운로드 완료 여부는 알 수 없습니다.
- 처리 시간은 앱 진입부터 마지막 응답 body의 ASGI send 처리까지입니다. 네트워크 왕복·클라이언트 다운로드 완료 시간 또는 순수 DB 조회 시간과는 다릅니다.
- 응답 본문·Authorization·Cookie·발급한 S3 서명 URL을 수집하지 않습니다.
  허용한 데이터 조회 파라미터의 값만 저장하고, 나머지 파라미터 값은 `[REDACTED]`로 바꿉니다.
  요청 경로 2,048자, User-Agent 512자, 쿼리 8KiB/32개/값 256자로 제한합니다.
- 워커별 최대 2,000건 큐, 최대 100건씩 묶어서 MongoDB에 비동기 저장합니다.
  정상 상황에서는 약 0.25초 + DB 처리 시간 후 조회에 반영됩니다.
- DB 쓰기 시간 제한은 배치당 2초입니다. DB 장애·큐 포화 시 원래 API 응답을 유지하고
  `REQUEST_LOG_FALLBACK`으로 마스킹된 로그를 서버 표준 로그에 남깁니다.
  이 대체 로그는 대시보드에 자동 재수집되지 않습니다.
- 종료 시 최대 8초간 큐 저장을 기다립니다. 강제 종료 시 메모리 큐 기록이 사라질 수 있는 best-effort 방식입니다.
  모든 요청의 영구 보존을 보장하는 감사 시스템은 아닙니다.
- 대시보드의 저장 상태 경고는 해당 조회를 처리한 워커 기준입니다.
  여러 워커의 상세 상태는 서버 로그에서 확인해야 합니다.
- MongoDB 4.4 호환 집계 연산을 사용합니다. P95는 선택 조건의 처리 시간을 정렬한 nearest-rank 값입니다.
  실시간 기록이 저장되는 중에는 연속 조회 간 집계·페이지 경계에 변화가 있을 수 있습니다.
- 대시보드 집계는 쿼리당 5초, 요청 전체 12초로 제한합니다. 이용량이 커지면 사전 집계 도입을 고려하세요.

기존 `/api/griddata`의 동기 S3 다운로드·계산 처리는 이번 변경 범위에 포함하지 않았습니다.
해당 작업이 이벤트 루프를 오래 점유하면 같은 워커의 대시보드·로그 저장도 늦어질 수 있습니다.

## 검증

`tests/test_monitoring.py`는 FastAPI TestClient와 MongoDB 모의 컬렉션을 사용합니다.
테스트용 환경에서 기존 의존성 외에 `pytest`, `httpx`, `mongomock`을 설치한 뒤 실행하세요.

```bash
python -m pytest tests/test_monitoring.py -q
```

확인 항목: 정상·404·422·500, 스트리밍, GET만 기록, 임의 IP 헤더 비신뢰,
토큰 마스킹, 인증, 빈 상태, 통계·P95·검색·페이지·UTC 처리,
정적 파일·문서·리다이렉트 분류, DB 장애 시 API 유지, 큐·쿼리 길이 제한.
실제 운영 MongoDB·S3·프록시 연결 및 운영 부하 테스트는 수행하지 않았습니다.
화면은 샘플 응답을 사용한 로컬 브라우저 검증 대상입니다.
